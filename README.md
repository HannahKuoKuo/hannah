# 建案預售/接待中心廣告到達頁（一頁式網站）

純 HTML / CSS / JS 打造的一頁式 Landing Page，設計目的是承接建案廣告流量（Google Ads / Meta 廣告等），導向「預約賞屋」表單，供接待中心後續跟進客戶。

## 檔案結構

```
index.html   單頁內容（Hero、建案亮點、地段交通、格局規劃、接待中心資訊、FAQ、預約表單、頁尾）
styles.css   樣式（手機優先，含響應式）
script.js    表單送出邏輯、動態年份
assets/      圖片素材（目前為佔位圖，請替換成正式素材）
```

## 頁面內容架構

- **Hero**：建案名稱、地區定位、坪數/戶數/樓層/交屋時間等基本資訊、CTA 按鈕
- **建案亮點**：地段、生活機能、建築工法、公共設施四大重點
- **地段交通**：生活機能條列 + 地圖嵌入位置（預留 Google 地圖 iframe）
- **格局規劃**：各戶型坪數卡片（可依實際規劃增減）
- **接待中心資訊**：地址、開放時間、洽詢專線
- **常見問題**：付款方式、車位、交屋時間等預售屋常見問題
- **預約賞屋表單**：姓名、電話、Email、房型興趣
- **頁尾**：建商資訊 + 房地產廣告免責聲明（見下方合規提醒）

## 本機開發

```bash
npm run dev
```

會啟動本機伺服器（http://localhost:3000），修改 index.html / styles.css / script.js 後重新整理瀏覽器即可看到變化。

## 房地產廣告合規提醒（重要）

台灣房地產預售廣告受《公平交易法》與內政部《預售屋買賣定型化契約應記載及不得記載事項》規範，建議上線前請業主/法務確認：

- 頁尾已加入基本免責聲明（示意圖說明、以政府核准文件及正式契約為準），但**實際文字建議由業主法務或代銷公司審閱**
- 坪數、格局、公設項目等數字若尚未經建照核准確定，避免寫死絕對數字，改用「規劃」「暫訂」等用語
- 若有「使用執照」「建造執照」字號，可考慮於頁尾補充揭露
- 廣告中若涉及房價、優惠方案，需確認是否符合當地代銷業者的揭露規定

## 部署建議

靜態網站，可直接部署到免費的靜態託管服務：

- **Cloudflare Pages**：連接 GitHub repo，自動部署，速度快、有台灣附近的 CDN 節點
- **Vercel** / **Netlify**：同樣支援連接 repo 自動部署
- **GitHub Pages**：免費但自訂網域設定稍微多一步

部署後記得：
1. 綁定正式網域（例如 `case.yourbuilder.com`）
2. 確認手機版顯示正常（廣告流量大多來自手機）
3. 用 Google PageSpeed Insights 測一下速度，影響廣告品質分數與轉換率
